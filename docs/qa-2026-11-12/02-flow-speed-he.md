# 02 · מהירות שימוש: נגיעות, השהיה נתפסת ותזמוני API

תאריך: 2026-11-12. הבדיקה כללה קריאת קוד ומדידות מול ה-API המקומי ב-`:3031`. לא הורץ סימולטור ולא שונה אף קובץ בפרויקט.
הכניסה בוצעה כמו ב-`auth_api.dart`: login, קוד MFA במייל, ואז device-token. ה-token בוטל בסיום (`/mobile/logout` החזיר 401 בבדיקה החוזרת).
מסד הנתונים: עסק "סטודיו תבל לדוגמה" עם 820 מסמכים ו-521 לקוחות.
המספרים נמדדו על loopback, בזמן שהרצת QA אחרת רצה במקביל. ב-production צריך להוסיף RTT של סלולר (כ-60–120ms) לכל קריאה **סדרתית**.

## 1. נגיעות לפי מסע

כללי הספירה הם לפי SPEC-v2 §1 F3.1. הערכים "היום" לקוחים מבדיקות ה-AT שמונות `tap()` דרך TapCounter (`integration_test/v2_qa-compose_test.dart`, `v2_qa-people_test.dart`), ובמסעות שאין להם AT, מהקוד.

## 3. תזמוני API

כל endpoint נמדד 5 פעמים, ומוצג ה-p50. זמני השרת לשרשרת ההפקה לקוחים מ-`/tmp/invoiceproject-mobile-dev.log`, כ-700 בקשות של QA מוקדם יותר.

| Endpoint | p50 | גודל | הערה |
|---|---|---|---|
| `/mobile/session` · `/me` · `/business/profile` · `/billing/subscription` | 12 · 42 · 12 · 19ms | <2KB | ארבע קריאות סדרתיות בפתיחה |
| `/mobile/inbox?limit=10` | 38ms | 4.7KB | מצוין |
| `/customers?sort=recent&limit=500` | **250–450ms** | **181KB** | עם limit=50 לוקח 15ms. **N+1 ב-SQL**: 5 תת-שאילתות מתואמות לכל שורה (`packages/postgres/src/customers.ts:226-262`) |
| `/documents?limit=500` | 240ms | 263KB | פתיחת L |
| `/documents?unpaid=1&limit=500` | 35ms | 180KB | פתיחת L |
| `/settings/branding` | 230ms | **647KB** | הלוגו מגיע inline כ-data URI |
| `/documents/:id` · `/pdf` | 56 · 129ms | 2KB · 580KB | כל פתיחה של D |
| `/tax-rates` · `/sequences` | 19ms · — | <1KB | חוסמים את C ואת ההפקה |
| **שרשרת ההפקה (שרת)**: documents 10 · finalize 25 · artifact **176** (p99 814, מקסימום **21.3s** היום) · payments 7+8 · share-link 6ms | | | בסך הכול כ-250ms בשרת; ב-production ה-RTT הוא הגורם הדומיננטי |

אין gzip ואין ETag (`Cache-Control: no-store`) על אף תגובה, ולכן 181KB ו-263KB עוברים במלואם בכל רענון.

**דפוסים פטפטניים:**
1. שרשרת ההפקה: כ-12 round-trips.
2. `sendReminders` מבצע `send` ואז `process` לכל מסמך, כלומר 2N (`inbox_api.dart:587`).
3. החיפוש לפי ת״ז מוציא קריאה נפרדת לכל לקוח (`inbox_api.dart:755`).
4. רשימת הלקוחות (500 לקוחות) נמשכת מחדש בכל פתיחה של S2 ובכל פתיחה של P.

## 4. רינדור כבד

- **L**: `ListView(children:)` בונה מראש עד 500 שורות, ובונה אותן מחדש בכל הקשה בשדה החיפוש (ובכל פעם רץ גם `groupByMonth`) (`activity_screen.dart:611`). בכל טעינה כל 1,000 המסמכים עוברים `jsonEncode` ונכתבים עם fsync על ה-main isolate (`:140`).
- `jsonDecode` רץ על ה-main isolate (`client.dart:219`). בפתיחת L מגיעים כ-460KB, בזמן אנימציית המעבר, ולכן צפוי jank. ה-isolate מנוצל רק לדחיסת JPEG (`expenses_api.dart:52`).
- PDF של 580KB מוצג inline ב-`PdfViewPinch` בכל פתיחה של D (`document_parts.dart:36`).
- ✓ P משתמש ב-`ListView.builder` (`people_screen.dart:361`). בסך הכול יש 28 מופעים של `ListView(` ורק 3 builders.
- **באג נתונים שנמצא בדרך:** ה-theme קבוע על dark (`main.dart`, `themeMode: ThemeMode.dark`). לכן לכל לקוח בלי טלפון מוצג המספר הבדוי **052-0000111** (`s2_customer.dart:494,539`; `people_screen.dart:385`; `customer_chip.dart:32`).
