# 06 · ניתוח סטטי של זרימות משתמש (iOS) — 12.11.2026

הבדיקה נעשתה בקריאת קוד בלבד, בלי סימולטור. המקורות: `router.dart`, `app_shell.dart`, כל קריאות `open*`, `push` ו־`show*Sheet` תחת `lib/screens/**`, ו־`state/caps.dart`. ההשוואה היא מול SPEC-v2 §4.4–§7. ממצאים שכבר ידועים לא נכללו כאן.

## 1. גרף המסכים בפועל

```
Splash → Login(/gate) → [MFA] → [S14 חובה אם >1 עסק] → [Setup] → AppShell
AppShell = PageView ללא החלקה: [בית] [ניהול] [פרופיל]; "חשבונית" (＋) צף רק בלשונית בית
│  (לשונית "לקוחות" נטענת ב-PageView אבל אין לה כפתור בסרגל)
├ בית H
│  ├ אווטאר → לשונית פרופיל ; כותרת (>1 עסק) → S14 → resetToHome
│  ├ כרטיס כסף → L(לא שולם)
│  ├ עיגולים: מסמכים→L · קיבלתי→C(PAID) · הוצאות→E-overview|E · בקש→C(REQUEST)
│  ├ תזכורות CRM → לוח מעקב(/crm/agenda) → P2
│  ├ לטיפול (3) → D | C | L(inbox) | E | B-section | "שלח תזכורות" (שולח מיד)
│  └ אחרונים → D ; ⋯ מחק טיוטה (עם אישור) ; "לכל החשבוניות" → L
├ C (fullscreen, אין swipe) → S2 (עמוד) → סכום → S3 (sheet) → ראשי → D (replace) + S6 אוטומטי
├ D → ⋯ / ראשי → S5 · S6 · S8 (sheets) · דיאלוגים ; זיכוי → D(זיכוי) push ; שכפל → C(draft) ; PDF → מסך מלא
├ ניהול B: רשת פעולות מהירות (≤8 + "עוד") + 14 שורות
│  ├ לקוחות → P (לשונית; חזרה = הלשונית הקודמת, אין swipe) → P2
│  ├ לוח מעקב · הצעת מחיר→C · לקוח חדש→S2 · דוחות→R→R2 · עיצוב · צוות→S13
│  ├ חיבורים→Cardcom · פרטי העסק→EditorPage · סוגי מסמכים→C · מספור→S13
│  └ שורות: פרטי העסק→S13 sheet(!) · אישורים · מסלול→Plans→Checkout · התראות · החשבון שלי→מחיקה
├ P2: חייג/WA/מייל · פאנל CRM (דיאלוגים) · ראשי→C(REQUEST) · עריכה→S2 · כרטסת · ⋯ ארכב→pop
└ פרופיל: מתג [פרופיל = טופס 13.1 "פרטי העסק"] / [הגדרות = AccountPage] + כפתור "המסלול"
```

**ההבדלים בין התפקידים:**
- **עובד:** אין כרטיס כסף. העיגולים הם מסמכים, הוצאות→E, בקש, ו"קיבלתי" רק למי שמורשה גם להפיק. ב־C הכפתור הוא "שלח לאישור". בניהול: לקוחות, לוח מעקב, הצעה, לקוח חדש וסוגי מסמכים, ובשורות: הוצאות, התראות, החשבון שלי. ב־P2 אין פאנל CRM, עריכה או ארכוב, אבל לוח המעקב פתוח לו.
- **רו״ח:** לשונית בית מציגה את R (כולל החלפת עסק), ומשם R2. אין ＋. בניהול: לקוחות ולוח מעקב, ובשורות: הוצאות (overview לאישור), רשות המסים, התראות, החשבון והמשך במחשב.
- **צפייה:** בבית רק "מסמכים" ו"אחרונים", בלי "לטיפול". בניהול: לקוחות ולוח מעקב.
- **לכל התפקידים:** לשונית "פרופיל" פותחת טופס עריכה של פרטי העסק (ראו U1).

**חזרה:** כל המסכים שנדחפים הם `CupertinoPageRoute` עם swipe-back, חוץ מ־C (fullscreenDialog, בלי swipe) ומהלשונית P (שהיא דף ב־PageView ולא route).

## 3. חיכוך UX (לפי השפעה)

### H
- **U1 · לשונית "פרופיל" היא פרטי העסק, לכל תפקיד** (profile_settings_screen.dart:196). עובד, צופה ורו״ח רואים טופס 13.1 עם בנק ופרטי רו״ח וכפתור "שמור" שייכשל בשרת. זה עוקף את `/business/profile`, שמוגן ב־`settingsBusiness`. בנוסף, המשתמש מצפה לראות שם את הפרופיל האישי שלו. גם כפתור "המסלול" מוצג לכל תפקיד (שורה 106). **מאמץ: S**
- **U2 · אין יציאה מ־C אחרי שנבחר לקוח.** כפתור החזרה היחיד (compose_screen.dart:337) קורא ל־`_backToCustomerPicker` (שורה 207), שפותח מחדש את בורר הלקוחות. ביטול הבורר משאיר את המשתמש ב־C. המסך הוא fullscreenDialog, אז אין גם swipe. כך זה גם כשנכנסים עם `customerId` או `draftId`, ובמקרה הזה הכפתור אפילו מציע להחליף את הלקוח של הטיוטה. הבדיקות מכסות רק ביטול לפני שנבחר לקוח. כדאי לוודא בסימולטור. **מאמץ: S**
- **U3 · מסכי "לא זמין" ושגיאה ב־C בלי כפתור חזרה** (compose_screen.dart:224–230). מגיעים אליהם, למשל, מקישור עומק לסוג מסמך שאסור לעסק. זה מבוי סתום מלא. **מאמץ: S**
- **U4 · "שלח תזכורות" בנגיעה אחת על שורת הסיכום** (inbox_cards.dart:196, 279) שולח מייל לכל החייבים בלי תצוגה מקדימה, בלי אישור ובלי ביטול. נגיעה כדי "לקרוא" את השורה כבר שולחת. רשימת הלקוחות לשליחה בווטסאפ זמינה רק דרך פעולה בתוך toast של כמה שניות. כשה־toast נעלם, הרשימה אובדת. **מאמץ: M**

### M
- **U5 · טיוטה מקומית בלתי נראית:** `saveLocalDraft` (compose_screen.dart:155) שומר slot אחד לכל עסק לפי intent. הטיוטה משוחזרת בשקט בפעם הבאה שנפתח אותו intent (compose_loader.dart:136), עם לקוח וסכום ישנים, ואין כרטיס או הודעה שמסבירים את זה. בנוסף, "חשבונית" (TYPE:305) ו"בקש תשלום" (REQUEST) יוצרים אותו מסמך אבל שומרים טיוטה ב־slot שונה. **מאמץ: M**
- **U6 · כרטיס UNFINISHED בלי draftId** (inbox_cards.dart:171–184) פותח C(REQUEST) ריק. יומן ההפקה המקומי משוחזר רק כשיש `draftId` (compose_loader.dart:116). **מאמץ: S**
- **U7 · כרטיס QUOTE_ACCEPTED ממיר את ההצעה ברגע שנפתח C** (compose_loader.dart:112). אם המשתמש חוזר אחורה, ההצעה כבר מסומנת CONVERTED ונשארת טיוטה יתומה. **מאמץ: S**
- **U8 · אובדן קלט בלי אישור:**
  - S13 (s13_editor.dart:54) נסגר בגרירה או בנגיעה מחוץ לטופס, וזה כולל את טופס 13.1 הארוך.
  - S5 עם פרטי צ'ק (s5_payment.dart:21).
  - S2 "לקוח חדש" או עריכה (s2_customer.dart:989, `canPop` true).
  - דיאלוגי CRM, שנסגרים בנגיעה ברקע (customer_crm_editors.dart:15/93/110).
  - מיתוג: יש `_dirty`, אבל אין `PopScope`.

  זה הממצא מהביקורת של 11-04 על "שמירת טיוטה בטפסים ארוכים", והוא **לא תוקן**. **מאמץ: M**
- **U9 · אותה פעולה בשלוש צורות:**
  - "פרטי העסק" נפתח כעמוד מהפעולה המהירה, כ־sheet מהשורה וכלשונית "פרופיל" (business_screen.dart:237, 431).
  - "המשך במחשב" נפתח פעם כעמוד ופעם כ־sheet.
  - "חשבונית" הצפה ו"בקש תשלום" זהות (intent_resolver.dart:23, 45).

  משתמש חדש לא יבין מה ההבדל ביניהן. **מאמץ: S**
- **U10 · P היא לשונית ולא route:** אין swipe-back, והחזרה הולכת ל"לשונית הקודמת" ולא למקום שממנו הגיעו (app_shell.dart:182). הסרגל מסמן "ניהול" כשנמצאים ב־P. **מאמץ: M**
- **U11 · קישור או התראה למסלול אסור נכשלים בשקט:** `go` מחזיר false (router.dart:284) ואין שום הודעה. התראה שמגיעה כשהאפליקציה פתוחה מוצגת כ־notice לא לחיץ (system_notices.dart:196), והמסלול שבה נזרק. **מאמץ: S**
- **U12 · חריגות שאינן `ApiException` ב־C** (compose_submit.dart:243), למשל `PlatformException` מ־`launchAllowed`, לא נתפסות. המשתמש לא מקבל הודעה, והכפתור פשוט חוזר למצב רגיל. **מאמץ: S**
- **U13 · לוח מעקב CRM פתוח לכל תפקיד** (business_screen.dart:354, בלי בדיקת `can`), בעוד שהפאנל ב־P2 מחייב `customerManage`. **מאמץ: S**

### L
- **U14 · "לקוח חדש" מ־ניהול:** אחרי השמירה התוצאה נזרקת (business_screen.dart:484). מ־P המשתמש חוזר לרשימה, לא לכרטיס החדש. **מאמץ: S**
- **U15 · החלפת עסק מ־ניהול:** `resetToHome` (s14_switch.dart:140) מעביר את המשתמש ללשונית בית. **מאמץ: S**
- **U16 · עודף משוב אחרי הפקה:** toast משלוח, toast של "פעם ראשונה", באנר ב־D ו־S6 שנפתח לבד, הכל באותו רגע. ב־S5 יש גם באנר וגם toast. **מאמץ: S**
- **U17 · אין pull-to-refresh** ב־E (expenses_screen) ובלוח המעקב. **מאמץ: S**
- **U18 · מסך הדגמה ב־debug:** במצב debug נדחף מסך הדגמה `/demo/customer-payment` אחרי הפקת מסמך גבייה (compose_submit.dart:~200). זה משנה את הזרימה שאתה רואה בסימולטור. **מאמץ: S**
- **U19 · שכפול לא אחיד:** שכפול מסמך פותח את C, ושכפול הצעה פותח את D של טיוטה חדשה. **מאמץ: S**

## 5. מעקב אחרי UX-AUDIT-2026-11-04

- **נבדק ונמצא תקין:** הקבלה מוצגת ב־`BoxFit.contain` (expense_review_card.dart:227, 338). ב־13.1 יש כותרות קבוצה ("זהות העסק" ואחרות).
- **לא תוקן:** טפסים ארוכים עדיין בלי שמירת טיוטה ובלי אישור לפני יציאה (U8).
- **השתנה:** הפער בין המיתוג במובייל ל־web הוכרע לטובת מצב כהה בכפייה. בגלל זה כל ענפי מצב בהיר מתים, וחלקם מסתירים תוכן (G5, G6).
- **שאר הסעיפים** נוגעים ל־web או לתהליך, ולא נבדקו כאן.
